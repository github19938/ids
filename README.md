# id_photo_suit — Automatic ID-Photo Suit Replacement

A modular, CPU-friendly Python pipeline that takes an arbitrary portrait
photo, detects the subject's shoulders/neck, and composites a formal
suit template onto the body **without** disturbing the face, hair, or
the natural neck-to-collar transition.

The system is deliberately built as a small library (one module per
responsibility) rather than a single notebook so it can be embedded
in a service, swapped piece-wise (e.g. plug in a stronger segmentation
backbone), and unit-tested.

## Quick start

```bash
# 1. Build the default suit template (only needed once).
python3 tools/build_default_template.py

# 2. Run on a real portrait.
python3 -m id_photo_suit \
    --input ./my_portrait.jpg \
    --template ./templates/default_suit \
    --output ./my_id_photo.jpg

# 3. Or programmatically:
python3 -c "from id_photo_suit import run; run('my_portrait.jpg', 'templates/default_suit', 'out.jpg')"
```

The deterministic self-test (no real photo required, validates every
algorithmic path) lives at `tools/smoke_test.py`:

```bash
python3 tools/smoke_test.py
```

## Pipeline at a glance

```
input image
   │
   ▼  pose.py        →  PoseKeypoints (left/right shoulder, neck, chin)
   │
   ▼  segmentation.py →  PortraitMasks (person, face, hair, neck, upper_body)
   │
   ▼  template_loader.py →  GarmentTemplate (body RGBA, collar RGBA, anchors)
   │
   ▼  align.py        →  2x3 similarity matrix (scale + rotate + translate)
   │
   ▼  cv2.warpAffine  →  body & collar warped into portrait coords
   │
   ▼  color_match.py  →  LAB mean/std harmonization (suit toward portrait)
   │
   ▼  render.py       →  background → body → collar → neck → face → hair
   │                     (each layer feathered, mask-occluded, premultiplied)
   ▼
output image
```

---

## Why a similarity (not full affine) transform?

We solve for **uniform scale + rotation + translation** with three
fiducials:

```
template.left_shoulder   →  portrait.left_shoulder
template.right_shoulder  →  portrait.right_shoulder
template.neck            →  portrait.neck
```

A full 6-DoF affine could shear the suit (e.g. make a lapel slant
asymmetrically) which destroys realism.  A similarity gives us "stretch
the template uniformly to the right size, then rotate to match the
shoulder line, then translate to where the neck is."  Both `body.png`
and `collar.png` are warped with the *same* matrix so they remain
registered to each other.

---

## Layered rendering, in order

The renderer (`render.py`) draws strictly bottom-up:

1. **background** – original photo or replacement BG.
2. **body** – warped suit, alpha = `template_alpha · (1 − protect) · person_dilated`.
3. **collar** – same protect mask, drawn on top of the body.
4. **neck** – the *original* portrait pixels in the neck strip, re-pasted
   so the collar/skin transition is the subject's real skin.
5. **face** – original face pixels, re-pasted (face is never overwritten).
6. **hair** – original hair pixels, drawn last so flyaways correctly
   occlude the collar.

`protect = face ∪ hair ∪ neck`, dilated by `protect_dilate_px` and
Gaussian-feathered.  This is the mechanism that **guarantees the face
and hair are never painted over** — verified by the deterministic test
(`face-pixel BGR delta: 0`).

Every alpha mask is feathered (`cv2.GaussianBlur`) before compositing so
no hard cut lines appear at any boundary.

---

## Quality contract (mapped to the spec)

| Requirement                            | How it's enforced                                     |
| -------------------------------------- | ----------------------------------------------------- |
| Don't cover face or hair               | `render.py` `protect` mask + face/hair re-paste pass  |
| Collar fits naturally to neck          | Shared affine matrix + neck strip preserved as-is     |
| No visible seam edges                  | Gaussian-feathered alpha on every layer (configurable)|
| Multiple garment templates supported   | `template_loader.list_templates(root)` + per-template `config.json` |
| < 1 s on CPU                           | Pipeline downsizes to `max_long_edge=1280` by default |
| No "just resize" placement             | True 2-D similarity solve from 3 fiducials            |
| Hard edges forbidden                   | `feather_px > 0` enforced in `RenderConfig`           |
| All knobs adjustable                   | CLI flags + `PipelineConfig` + `config.json` overrides|

## Tunable parameters

CLI:

```
--scale-bias       multiplier on auto-computed garment scale (≈1.05 default)
--y-offset         vertical offset as fraction of shoulder width
--extra-scale      manual fine scale
--extra-angle      manual fine rotation (degrees, around shoulder centroid)
--extra-offset-x   manual fine X translation (pixels)
--extra-offset-y   manual fine Y translation (pixels)
--max-edge         downscale long edge before processing (0 disables)
--no-color-match   disable LAB color harmonization
```

Per-template overrides in `config.json`:

```json
{
  "body_image":   "21.png",
  "collar_image": null,
  "render":      { "feather_px": 6, "scale_bias": 1.05, "y_offset_ratio": 0.02 },
  "color_match": { "enable": true, "strength": 0.35, "match_chroma": false }
}
```

`body_image` (optional, defaults to `body.png`) selects which RGBA file
inside the template directory is used as the garment body.  Set
`collar_image` to `null` (or simply omit it) when the body image already
contains the collar / tie / accessories baked in — the renderer will
then skip the separate collar layer entirely.  The historical
`body.png` / `collar.png` filenames continue to work without any change
to existing templates.

Programmatic:

```python
from id_photo_suit.pipeline import SuitPipeline, PipelineConfig
from id_photo_suit.render import RenderConfig
cfg = PipelineConfig()
cfg.render = RenderConfig(feather_px=8, protect_dilate_px=3, final_sharpen=0.2)
with SuitPipeline(cfg) as p:
    out = p.process_path("in.jpg", "templates/default_suit", "out.jpg")
```

## Performance notes

On a typical mid-range CPU:

| Stage                 | Cost  |
| --------------------- | ----- |
| MediaPipe Pose        | 60 – 120 ms |
| MediaPipe FaceMesh    | 25 – 60 ms  |
| SelfieSegmentation    | 25 – 80 ms  |
| Affine + warpAffine x2 | < 5 ms     |
| Color matching        | 5 – 15 ms  |
| Layered render        | 15 – 40 ms |

The pipeline downscales any input whose long edge exceeds `max_long_edge`
(default 1280) before processing, then up-samples the final composite,
which keeps total wall-time well under 1 s for typical phone-camera
inputs.  The deterministic self-test (no MediaPipe) finishes in ~300 ms
on this VM.

## Honest limitations

The task asked us to flag what *cannot* be implemented perfectly without
heavier ML, rather than silently paper over it.  Here is the list:

1. **Hair / clothes parsing is approximate.** MediaPipe's
   `SelfieSegmentation` returns a *binary* person/background mask, not a
   true face-parsing label map.  We synthesize hair as
   `person ∩ ¬face ∩ above_chin`, and the neck strip from FaceMesh
   geometry.  For long hair past the shoulders, or for unusual hairstyles,
   these heuristics under-segment.
   *Mitigation:* the segmentation backend is encapsulated behind
   `Segmenter.get_masks(image)`.  Drop in an ONNX BiSeNet / MODNet face-
   parsing model and the rest of the pipeline is unchanged.

2. **Original collar / clothes removal is NOT performed.** If the subject
   already wears a high-collared shirt or hooded jacket, the new suit is
   composited *on top of* the original upper-body pixels but the renderer
   still respects the `protect` mask, so where the original neckline rose
   above the new collar you may still see it.  A proper inpainting pass
   (e.g. LaMa) on the upper-body region would be the commercial fix.

3. **Default template is procedurally drawn**, not photographic.  This is
   so the project runs immediately after `pip install -r requirements.txt`.
   To reach commercial quality, replace `templates/default_suit/body.png`
   and `templates/default_suit/collar.png` with photographic RGBA assets
   and re-measure their `anchor_points` (in template pixels).  No code
   change is required.

4. **Lighting is matched in mean (and optionally std) — not direction.**
   Strong directional light on the subject won't be re-cast onto the
   suit; we only harmonize average brightness/chroma.  Re-lighting
   requires a normal-map or shading network, out of scope for a CPU
   real-time pipeline.

5. **MediaPipe Pose / FaceMesh need a recognizable human.** The
   deterministic self-test bypasses MediaPipe by feeding hand-crafted
   key-points.  On a real photo we depend on detection succeeding;
   when it doesn't, `pipeline.process` raises a clear error.

6. **3-D head pose is approximated as 2-D rotation.** A heavily yawed
   head will still get a frontally-shaped collar.  3-D-aware warping
   (PRN-style) is out of scope here.

These are deliberate engineering choices to fit the "<1 s CPU, minimum
deps" envelope.  Each is gated behind a clean module boundary so it can
be upgraded independently.
